# 新版运营工作台（未合并 / 待审核）

## 范围和入口

保持 FastAPI + async SQLAlchemy + aiogram。没有 Flask/Jinja 迁移、通用定时消息、资料历史版本/恢复，没有改访客首页卡片、尺寸、网格、页数或常驻「首页」菜单。

`/app/admin.html`、`/app/console.html`、`/app/desk.html` 均由现有 `bot/main.py::_admin_file` 返回新版 `desk.html`，HTML 保持 `no-store`。`console.html` 同步保留相同静态内容；`admin.html` 静态重定向也更新。新版为默认；顶栏「旧版后台」进入 `/app/desk-legacy.html`，仅是兼容UI，不绕过API鉴权。所有旧API仍可用。

新版/改动后台资产版本：**20261111a**（workspace boot/CSS/JS，admin.js、admin-ops、admin-proxy、admin-buttons、admin-coupons）。未改的 admin-list 保持 20261110f，消息样式/edit-state 保持既有版本；访客资产和 bot 菜单版本 **20261110h 不动**。

## 配置/API/权限

新增窄网关 `GET/POST /api/admin/workspace/config`：同一份现有 `SiteSettings` / `ops_config`，没有第二配置库。schema 覆盖 `CITY_KEYS`、原 `ExtraOpsBody`、站点公告/城市列表；POST `{city, section, changes}` 拒绝跨页字段，检查全站/城市/受保护权限，复用原类型、URL、按钮、频道验证及行锁保存。城市字段仍走原城市设置服务；城市公告改用新工作台专用**行锁局部补丁**，不覆盖别的城市或未改字段。现有旧公告API不改。

`GET /api/admin/workspace/posts/{id}` 同时校验待审Post的城市和当前目标资料的城市，返回真实 pending/current 做媒体对照。审批仍走原服务，不覆盖后续文字、不延长到期、不恢复非活跃状态；首次/完整资料审核按原服务保护处理。现有后端拒绝通知是固定内容，**不伪造未保存的自定义拒绝理由输入框**。

- 仍须 Telegram initData 鉴权，没有独立网页登录/密码框或匿名管理员绕过。
- 顶栏只有一处城市范围。不同城市响应过期会被丢弃，列表缓存切换清空；服务端仍是授权最终依据。
- 只读兼容跨城运营可以看其原有城市范围，不可据此写全站/城市配置。全站私聊日志依旧仅超管可见。
- 普通城市空值继承；频道链接标签空字符串仍表示隐藏，NULL 才恢复继承。
- **旧首页公告特例真实保留**：本城覆盖开启且正文非空才替换全站；关闭/清空本城公告只回落全站，不能单独隐藏已启用的全站公告。页面显示当前用户实际看到的内容/来源；不谎称每个城市公告开关都能禁用全站公告。城市公告无正文时不单独存开关，保存正文不会偷偷开启覆盖。
- 保存确认只提交当前页 changed 字段；导航/刷新提示未保存；保存中锁定输入和范围，防止响应覆盖新草稿。部分权限名单/城市分配保存失败会清楚提示哪一步未确认，不重复已成功的新增通知步骤。
- 设置用于后续消息；不自动改历史消息、不回填/补发。小程序仍可能缓存10/60秒；目录配置仍下次北京时间12:00应用，已有上/下架事件目录90秒合并、链接标签30秒合并保持不变。
- 私聊 WebApp / URL白名单及按钮平台限制继续由原渲染器执行；频道仍是正文文字深链，没有频道内联按钮。

## 新增三类日志：观察，不改变触发和重试语义

`bot/services/execution_trace.py` 为现有函数提供流程及实际Telegram调用阶段记录：

- 优惠：新优惠发送、结束/到期/停用编辑、领取完后的原帖刷新、链接同步编辑；10分钟既有结束任务标为 scheduled。
- 精选评价：原审核通过路径的 text-only 精选频道发送与引用保存；不推送凭证/照片。
- 按区目录：创建、原帖更新、关闭/频道切换的既有退役处理，以及手动服务调用、12:00任务、既有延后恢复、上/下架事件来源。

记录 feature/city/listing/op/step/source、开始结束、配置版本（业务取得时）、安全引用和分类原因；不存正文、initData、token、会话或原始错误。新阶段的 acknowledged 但引用提交失败标为 unknown；“not modified”编辑记录为 synced；关闭/无目标/无数据分别 skipped/not_configured。日志存储是既有 best-effort，DB诊断写入失败不阻止既有业务，不编造历史。

**没有给这三类增加通用重发或后台补发**，也没有声称给旧传输增加严格 exactly-once：既有 Telegram 传输/目录计划重试原样保留并逐次记录；首次发送不确定后即使既有重试后来成功，流程仍保守标记 unknown。它们在UI/API均不提供重发入口；实际发送和配置开关行为不因日志而改变。精选评价的审批去重仍由原审批入口控制，未在广播函数硬加新的去重政策。优惠结束路径原有“编辑失败仍落closed标记”的业务行为未改，日志会诚实记录失败。

PR58 的资料/续期通知/链接同步安全步骤重试继续委托原业务检查点和当前开关/城市权限；默认列表不会执行重试。unknown/sending、成功、开关跳过不新增盲目重发。

日志覆盖不是全应用审计：运营授权通知、用户封禁等仍用原运行日志，没有宣称这些操作都已统一入库；新来源字段在旧历史中为NULL。不做补录或审计历史/恢复第二批。
